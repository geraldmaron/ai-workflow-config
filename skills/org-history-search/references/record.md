# The record

The deliverable ends with a short block, exactly this shape:

```
Archaeology record
- Trace named:        answered, see <where>
- Chronology built:   answered, see <where> | gap remains: <yes/no>
- Vocabulary checked: answered, see <where>
- Layers worked:      answered, see <where>
- Thread read fully:  answered, see <where>
- Person consulted:   answered, see <where> | not reached: <reason>
- System of record:   answered, see <where> | not verifiable: <reason>
- Finding filed:      answered, see <where>
```

A gate that was not done says `not done: <reason>` in its slot. It is never
deleted and never skipped silently. Until every line is filled in, the
reconstruction is labeled a draft, by the person or process producing it, in
its own title line.

When several skills govern one deliverable, the skill that owns the
deliverable's shape produces the full record above, and this skill
contributes exactly one line to that record: its name, then its verdict or
a one-clause gate summary, never a second full block. Every "see <where>"
in any record carries a short quoted fragment of what it points to, not a
bare location, because a pointer that cannot quote its target is pointing at
nothing.
